\section{Purpose of the audit}

This report summarises my audit of the datasets and data-processing steps used in the inherited OpenFold retraining workflow.

The main purpose of the audit was to answer the following questions:

\begin{enumerate}[leftmargin=*]

    \item How does the OpenFold data compare with the PDB707K data used in the previous project?

    \item What data was used as input to the OpenFold retraining pipeline?

    \item Can the original dataset-selection procedure be reproduced from the material that was transferred to me?

    \item What are the inputs and outputs of AlphaFold, OpenFold, and the retrained OpenFold model?

    \item How do AlphaFold, OpenFold, and retrained OpenFold differ from each other?

    \item When comparing their predictions, what needs to be kept the same so that the comparison is fair?

\end{enumerate}

The audit is based on the project files that were transferred to me and that I later centralised under the \texttt{COMP702\_BeyondAF} project directory. These include the PDB707K dataset, OpenFold scripts, training scripts, notebooks, checkpoints, and prediction outputs.

Some inherited scripts contain paths under \texttt{/users/sgmwu14/...}. I do not have access to that account. I have therefore treated these paths only as historical information showing where data was originally stored.

All conclusions in this report are based on files that are currently available in my own project storage.


\section{Summary of the main findings}

The main findings of the audit are:

\begin{itemize}[leftmargin=*]

    \item The preserved checked PDB707K dataset contains \textbf{707,292 rows}.

    \item The inherited BRI notebook shows that the original PDB707K dataset contained \textbf{707,410 rows}. The difference is explained by a correction step in which 236 rows were removed and 118 corrected or reconstructed rows were added back:

    \[
        707{,}410 - 236 + 118 = 707{,}292.
    \]

    \item After filtering the checked PDB707K dataset to \texttt{model\_id = 1} and removing duplicate normalised chain identifiers, the reproducible dataset contains \textbf{461,578 unique chains}.

    \item The previous project reports \textbf{130,413 processed OpenFold alignment identifiers}, with a reported intersection of \textbf{65,656 chains} with PDB707K.

    \item The reported PDB707K-side counts are arithmetically consistent:

    \[
        707{,}410 - 65{,}656 = 641{,}754.
    \]

    \item The reported OpenFold-side counts are not consistent with a simple set subtraction:

    \[
        130{,}413 - 65{,}656 = 64{,}757,
    \]

    while the previous project reports \textbf{67,181 OpenFold-only chains}. This leaves a difference of \textbf{2,424 chains}.

    \item The downstream OpenFold retraining pipeline can be reconstructed from the inherited scripts and notebooks.

    \item The exact upstream step that created the training alignment subset cannot be reproduced because the original chain lists, matching script, and alignment subset were not included in the material transferred to me.

    \item AlphaFold and OpenFold use the same general type of information for structure prediction: a target protein sequence, multiple sequence alignment information, and structural template information where available.

    \item The retrained OpenFold model uses the same OpenFold implementation as the pretrained OpenFold model. The main difference is the model checkpoint, which contains parameters learned during the inherited retraining process.

    \item Therefore, when comparing pretrained OpenFold and retrained OpenFold using the same input features, the main variable being tested is the effect of the retrained model parameters.

\end{itemize}

\section{OpenFold duplicate-chain handling}

Another relevant part of the audit was understanding how OpenFold handles redundant chains.

OpenFold uses a file called:

\begin{center}
\texttt{duplicate\_pdb\_chains.txt}
\end{center}

The inherited OpenFold documentation describes this file as grouping PDB chains that are sequence-identical.

I also checked the inherited OpenFold source code in:

\begin{center}
\texttt{create\_alignment\_db\_sharded.py}
\end{center}

For each duplicate group, OpenFold:

\begin{enumerate}[leftmargin=*]

    \item searches the group for the first chain that already has alignment data;

    \item uses that chain as the alignment representative;

    \item maps the remaining chain identifiers in the group to the same alignment database entry.

\end{enumerate}

Therefore, duplicate chain identifiers are not necessarily removed completely. Instead, sequence-identical chains can refer to the same stored alignment data.

This is important for the next stage of the project because it gives a useful comparison with geometric de-duplication.

\section{Comparison of AlphaFold, OpenFold and retrained OpenFold}

\subsection{What the three models represent}

There are three prediction setups that need to be compared in this project:

\begin{enumerate}[leftmargin=*]

    \item \textbf{AlphaFold (AF)}

    \item \textbf{Pretrained OpenFold (OF)}

    \item \textbf{Retrained OpenFold}

\end{enumerate}

These should not be considered three completely unrelated models.

AlphaFold provides the original AlphaFold2 protein structure prediction system.

OpenFold is an independent implementation of the same general AlphaFold2-style model. One important advantage of OpenFold for this project is that it provides a training pipeline, which makes it possible to retrain the model.

The retrained OpenFold model is therefore still an OpenFold model.

The main difference between:

\begin{center}
\textbf{Pretrained OpenFold}
\end{center}

and

\begin{center}
\textbf{Retrained OpenFold}
\end{center}

is the set of model parameters stored in the checkpoint.

The overall OpenFold architecture and prediction pipeline remain the same.


\subsection{How AlphaFold works}

At a high level, AlphaFold starts from the amino-acid sequence of the target protein.

It uses information from related protein sequences to create a multiple sequence alignment, or MSA.

The MSA provides evolutionary information about the protein. AlphaFold can also use information from known protein structures as templates.

The main input information is therefore:

\begin{itemize}[leftmargin=*]

    \item the amino-acid sequence of the target protein;

    \item multiple sequence alignment information;

    \item structural template information, where available.

\end{itemize}

These features are processed by the neural network to learn relationships between residues in the protein.

The final part of the model predicts the three-dimensional positions of the atoms.

The main output relevant to this project is therefore a predicted three-dimensional protein structure.

The prediction can then be relaxed to improve local structural geometry.


\subsection{How OpenFold works}

OpenFold follows the same general prediction process as AlphaFold.

The input is again based on:

\begin{itemize}[leftmargin=*]

    \item the target amino-acid sequence;

    \item multiple sequence alignment information;

    \item structural template information, where available.

\end{itemize}

These inputs are converted into features and passed through the OpenFold neural network.

The model then predicts the three-dimensional structure of the protein.

The main difference is that OpenFold provides a training pipeline that allows the model parameters to be trained or retrained.

This is the reason OpenFold is important for this project.

The standard pretrained OpenFold model uses previously trained model parameters.

The output relevant to the current project is again a predicted protein structure in PDB format, with relaxation applied where required.


\subsection{How retrained OpenFold works}

The retrained OpenFold model uses the same general OpenFold prediction pipeline.

During inference, it receives the same types of input as pretrained OpenFold:

\begin{itemize}[leftmargin=*]

    \item the target protein sequence;

    \item alignment-derived features;

    \item template-derived features where available.

\end{itemize}

The difference is the checkpoint loaded into the model.

For pretrained OpenFold:

\begin{center}
OpenFold architecture + standard pretrained parameters
\end{center}

For retrained OpenFold:

\begin{center}
OpenFold architecture + parameters learned during the inherited retraining run
\end{center}

The inherited retrained prediction workflow uses checkpoint material associated with:

\begin{center}
\texttt{32-330000.ckpt}
\end{center}

Therefore, when pretrained OpenFold and retrained OpenFold are given the same inference inputs, the main difference between the two predictions should come from the different model parameters.


\subsection{Training input and inference input are different}

One important distinction is that the data used to \textbf{train} OpenFold is different from the data given to the model when predicting a new structure.

During retraining, the workflow uses:

\begin{itemize}[leftmargin=*]

    \item known protein structures in mmCIF format;

    \item sequence alignment data;

    \item chain information;

    \item sequence clusters;

    \item cached structural information;

    \item template-related information.

\end{itemize}

These data are used to update the model parameters and produce a trained checkpoint.

During prediction, the trained model is then given a target protein sequence and its associated sequence/template features.

It predicts a structure without being given the experimental structure of that target as the answer.

The process can therefore be summarised as:

\textbf{Training data}

\end{center}

\subsection{Main differences between the three}

The main difference between AlphaFold and OpenFold is the implementation.

They follow the same general type of protein structure prediction process, but they are separate implementations and use different sets of pretrained parameters.

Differences in their predictions may therefore come from:

\begin{itemize}[leftmargin=*]

    \item differences in model parameters;

    \item differences in the implementation;

    \item differences in MSA inputs;

    \item differences in template inputs;

    \item differences in inference settings;

    \item random seeds;

    \item relaxation settings.

\end{itemize}

The comparison between pretrained OpenFold and retrained OpenFold is more direct.

Both use the OpenFold implementation.

If the same sequence, alignment information, template information, and inference settings are used, then the main difference is:

\begin{center}
\textbf{the checkpoint used by the model.}
\end{center}

This makes the pretrained OpenFold versus retrained OpenFold comparison particularly useful for understanding the effect of the retraining procedure.


\subsection{What should be kept the same during comparison}

To make the comparison between AlphaFold, pretrained OpenFold, and retrained OpenFold meaningful, the inputs and evaluation conditions should be kept as consistent as possible.

For the same target chain, the comparison should ideally use:

\begin{itemize}[leftmargin=*]

    \item the same amino-acid sequence;

    \item the same or equivalent MSA information;

    \item the same or equivalent template information;

    \item the same template-date restrictions where possible;

    \item the same number of predictions;

    \item equivalent random-seed handling;

    \item the same relaxation procedure;

    \item the same structural evaluation method.

\end{itemize}

This is important because, if different MSA or template information is given to the models, a difference in the final prediction may be caused by the different inputs rather than the model itself.


\subsection{Outputs that should be compared}

The main output to compare is the predicted three-dimensional protein structure.

For each target chain, the comparison should include:

\begin{itemize}[leftmargin=*]

    \item AlphaFold predictions;

    \item pretrained OpenFold predictions;

    \item retrained OpenFold predictions;

    \item the experimental PDB structure, where available.

\end{itemize}

The following aspects can then be compared.


\subsubsection{Predicted structures}

The predicted PDB files can be compared directly to check whether the models predict similar overall structures.


\subsubsection{Relaxed structures}

Relaxation should be applied consistently so that the final structures being compared have undergone the same type of structural refinement.


\subsubsection{Consistency across repeated predictions}

Multiple predictions can be generated for the same chain.

This allows the consistency of each model to be examined.

For example, the current 2OLO-A baseline includes 100 independent predictions and 100 corresponding relaxed predictions from the retrained OpenFold checkpoint.

This allows the stability of the retrained model predictions to be examined rather than relying on a single prediction.


\subsubsection{Comparison with the experimental structure}

Where an experimental PDB structure is available, predictions from all three models can be compared with the experimental reference.

This provides an external reference when judging whether one model produces a structure that is closer to the known experimental structure.


\subsubsection{BRI, LAI and BTI comparison}

The project also compares predicted structures using BRI, LAI and BTI representations.

These allow backbone geometry to be compared in a way that is not dependent on the absolute position or orientation of the protein structure.

For each target chain, the comparison can therefore include:

\begin{itemize}[leftmargin=*]

    \item BRI profiles from AlphaFold predictions;

    \item BRI profiles from pretrained OpenFold predictions;

    \item BRI profiles from retrained OpenFold predictions;

    \item BRI profiles from the experimental structure;

    \item equivalent LAI and BTI comparisons.

\end{itemize}

This can show whether the three prediction methods produce similar backbone geometry and where local structural differences occur.


\subsection{Overall interpretation of the model comparison}

The three models should therefore be interpreted as follows:

\begin{center}
\textbf{AlphaFold}
\end{center}

provides the original AlphaFold prediction baseline.

\begin{center}
\textbf{Pretrained OpenFold}
\end{center}

provides a baseline from the OpenFold implementation using its standard pretrained model parameters.

\begin{center}
\textbf{Retrained OpenFold}
\end{center}

tests what changes when the OpenFold model parameters are replaced by parameters learned during the inherited retraining workflow.

The most controlled comparison is therefore between pretrained OpenFold and retrained OpenFold.

If both models use the same input features and prediction settings, differences between their outputs can be investigated as possible effects of retraining.

The AlphaFold comparison provides an additional reference to show how both OpenFold versions compare with the original AlphaFold prediction system.

\end{itemize}

The following parts cannot currently be reproduced exactly:

\begin{itemize}[leftmargin=*]

    \item the original list of 130,413 OpenFold identifiers;

    \item the exact 65,656-chain PDB707K/OpenFold intersection;

    \item the exact OpenFold-only set reported as 67,181 chains;

    \item the original OpenFold/PDB707K matching script;

    \item the exact chain membership of the original training alignment subset;

    \item the original chain-selection lists.

\end{itemize}

This means that the \textbf{downstream retraining pipeline is substantially reconstructable}, but the \textbf{exact upstream chain-selection procedure is not fully reproducible from the transferred files}.


\section{Conclusion}

The dataset audit has clarified the PDB707K data, the OpenFold retraining workflow, and the relationship between the three prediction setups used in the project.

The preserved PDB707K dataset contains 707,292 rows. I was able to trace this back to the original 707,410-row dataset and explain the difference as a correction procedure in which 236 rows were removed and 118 corrected or reconstructed rows were added back.

After applying \texttt{model\_id = 1} filtering and normalising chain identifiers, the reproducible PDB707K dataset contains 461,578 unique chains.

The previous project reports that 130,413 processed OpenFold identifiers were compared with PDB707K, producing an intersection of 65,656 chains. The PDB707K-side counts are consistent, but the reported OpenFold-only count differs from the value expected from a simple set subtraction by 2,424 chains.

The exact reason cannot currently be resolved because the original chain lists and matching script were not included in the transferred material.

The main inputs to the OpenFold retraining pipeline have been identified, and the downstream pipeline from the selected alignment subset to OpenFold training can be reconstructed. However, the exact step used to create the original alignment subset is not preserved.

The comparison between the three prediction setups is now also clear.

AlphaFold and OpenFold follow the same general type of sequence-, MSA-, and template-based structure prediction process.

The retrained OpenFold model uses the same OpenFold implementation as pretrained OpenFold, but loads a checkpoint learned during the inherited retraining workflow.

Therefore, for a controlled comparison, the same target sequence and equivalent inference inputs should be used across the models wherever possible.

The resulting PDB structures can then be compared with each other and with the experimental structure. Repeated predictions can be used to examine prediction consistency, while BRI, LAI and BTI can be used to compare the geometric behaviour of the predicted structures.

The pretrained OpenFold versus retrained OpenFold comparison is particularly important because, when the input features are kept the same, it provides the clearest way to examine the effect of the retraining procedure.

For the next dataset stage, the preserved set of 461,578 unique model-1 PDB707K chains provides a reproducible starting point for the new geometric de-duplication workflow.

The next planned step is to use BRI representations and $L_{\infty}$ distances to identify geometric near-duplicates and compare them with OpenFold's existing sequence-based duplicate handling.
