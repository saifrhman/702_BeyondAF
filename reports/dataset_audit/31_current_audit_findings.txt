14. OpenFold handling of duplicate PDB chains
The OpenFold resource duplicate_pdb_chains.txt groups sequence-identical
PDB chains. The inherited OpenFold code in create_alignment_db_sharded.py
shows that, for each duplicate group, OpenFold searches for the first chain
that already has alignment data in the alignment database index and uses it
as the alignment representative.

All other chain identifiers in that duplicate group are then mapped to the
same underlying alignment database index entry as the representative.

Therefore, these duplicate chain IDs are not necessarily removed from the
index. Rather, they share a single underlying alignment-data representation,
reducing redundant alignment storage.

This provides a sequence-identity-based redundancy baseline that can later
be compared with BRI-based geometric near-duplicate groups. It should not
be described as geometric de-duplication.

15. Explanation of the 707,410 versus 707,292 PDB707K discrepancy
The preserved BRI showcase notebook contains the workflow that produced
checked_PDB707K_cleaned_chains_sequences_19Feb2025.csv.

Notebook outputs show:
- Original PDB707K_cleaned_chains_sequences_19Feb2025.csv: 707,410 rows.
- After combining with the dataset named
  duplicated_PDB707K_cleaned_chains_sequences_19Feb2025.csv and applying
  drop_duplicates(keep=False): 707,174 rows.
- This corresponds to a reduction of 236 rows.
- A corrected/reconstructed dataframe called output was then appended.
- The final checked dataset contained 707,292 rows.
- Therefore output contained 118 rows, because 707,292 - 707,174 = 118.

The net transformation was therefore:
707,410 - 236 + 118 = 707,292.

This explains the previously observed 118-row difference between the
707,410 rows reported for the original PDB707K dataset and the preserved
707,292-row checked dataset.

The replacement dataframe was constructed by inner-merging
af_clean.csv with duplicated_PDB707K_cleaned_chains_sequences_19Feb2025.csv
on pdb_id, model_id, chain_id, and chain_length.

The available notebook evidence establishes the row-count transformation,
although the exact biological/data-quality reason each of the 236 original
rows was placed in the duplicated/problematic subset still needs to be
determined separately.
